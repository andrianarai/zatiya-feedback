# ЗАТІЯ — форма анонімного зворотного зв’язку

Готовий мобільний сайт для чотирьох пілотних зустрічей ЗАТІЇ. Усі відповіді потрапляють до однієї Google Таблиці, а стовпець `Meeting` показує номер зустрічі.

## Файли проєкту

- `index.html` — сторінка форми.
- `style.css` — мобільний дизайн.
- `script.js` — логіка форми та відправлення.
- `google-apps-script.gs` — код, який записує відповіді в Google Sheets.

## 1. Створіть Google Таблицю

1. Відкрийте [Google Sheets](https://sheets.google.com/).
2. Натисніть **Blank spreadsheet / Пуста таблиця**.
3. Назвіть файл, наприклад **ZATIYA Feedback**.
4. Унизу перейменуйте першу вкладку таблиці на **Responses**. Назва має бути написана саме так.
5. У першому рядку створіть шість заголовків:

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| Timestamp | Meeting | Rating | NewIdeas | Takeaway | Improvement |

6. Щоб час відображався правильно, відкрийте **File → Settings**, виберіть часовий пояс **(GMT+02:00) Kyiv** або актуальний київський часовий пояс і натисніть **Save settings**.

> Якщо вкладка `Responses` порожня або її ще немає, скрипт також уміє створити її та заголовки автоматично. Проте для першого налаштування краще виконати кроки вище вручну.

## 2. Додайте Google Apps Script

1. Не закриваючи Google Таблицю, натисніть **Extensions → Apps Script**.
2. Відкриється нова вкладка з редактором.
3. У файлі `Code.gs` видаліть увесь стандартний код.
4. Відкрийте файл `google-apps-script.gs` із цього проєкту.
5. Скопіюйте весь його вміст і вставте в `Code.gs`.
6. Натисніть значок дискети або `Ctrl+S` / `Cmd+S`.
7. Назвіть проєкт, наприклад **ZATIYA Feedback Backend**.

Оскільки Apps Script відкрито саме через цю Google Таблицю, він уже підключений до неї. Додатково вставляти ID таблиці не потрібно.

## 3. Опублікуйте Apps Script як Web App

1. У правому верхньому куті натисніть **Deploy → New deployment**.
2. Біля **Select type** натисніть значок шестерні.
3. Виберіть **Web app**.
4. У полі **Description** напишіть, наприклад, `ZATIYA feedback v1`.
5. У полі **Execute as** виберіть **Me**.
6. У полі **Who has access** виберіть **Anyone**.
   - Потрібно саме **Anyone**, а не **Anyone with Google account**, бо учасники не повинні входити в акаунт.
7. Натисніть **Deploy**.
8. Google попросить надати дозволи. Виберіть свій акаунт і підтвердьте доступ до таблиці.
   - Якщо з’явиться попередження про неперевірений застосунок, натисніть **Advanced**, потім перейдіть до власного проєкту й підтвердьте доступ. Це ваш власний скрипт.
9. Скопіюйте **Web app URL**. Правильна адреса закінчується на `/exec`.

Якщо варіанта **Anyone** немає, політика робочого або університетського Google-акаунта забороняє анонімний доступ. У такому разі створіть таблицю та скрипт у звичайному особистому Google-акаунті або зверніться до адміністратора домену.

## 4. Підключіть сайт до Apps Script

1. Відкрийте `script.js` у будь-якому текстовому редакторі.
2. На початку файлу знайдіть:

```js
const APPS_SCRIPT_URL = "PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE";
```

3. Замініть текст між лапками на скопійований Web app URL. Наприклад:

```js
const APPS_SCRIPT_URL = "https://script.google.com/macros/s/ВАШ_ID/exec";
```

4. Збережіть файл.

Не вставляйте адресу, яка закінчується на `/dev`: вона працює лише для власника скрипту.

## 5. Перевірте Apps Script

1. Вставте Web app URL із `/exec` у нову вкладку браузера.
2. Має з’явитися повідомлення: **«ЗАТІЯ — Сервіс приймання відгуків працює.»**
3. Якщо Google просить увійти в акаунт, поверніться до налаштувань deployment і перевірте, що **Who has access = Anyone**.

## 6. Створіть GitHub-репозиторій

1. Увійдіть на [GitHub](https://github.com/).
2. Натисніть **+** у правому верхньому куті → **New repository**.
3. Назвіть репозиторій `zatiya-feedback`.
4. Виберіть **Public**. Для безкоштовного GitHub Pages це найпростіший варіант.
5. Не додавайте README, `.gitignore` або ліцензію на цьому екрані.
6. Натисніть **Create repository**.

## 7. Завантажте файли на GitHub

1. На сторінці порожнього репозиторію натисніть **uploading an existing file**. Якщо репозиторій уже не порожній, натисніть **Add file → Upload files**.
2. Завантажте до кореня репозиторію:
   - `index.html`
   - `style.css`
   - `script.js`
   - `README.md` — необов’язково, але зручно зберегти інструкцію разом із проєктом.
3. Файл `google-apps-script.gs` теж можна зберігати в репозиторії як резервну копію. Він не виконується на GitHub Pages і не містить секретних ключів.
4. Унизу натисніть **Commit changes**.

Усі файли сайту мають лежати на одному рівні. `index.html` не потрібно класти в окрему папку.

## 8. Увімкніть GitHub Pages

1. У репозиторії відкрийте **Settings**.
2. У лівому меню виберіть **Pages**.
3. У блоці **Build and deployment** біля **Source** виберіть **Deploy from a branch**.
4. Біля **Branch** виберіть `main` і папку `/(root)`.
5. Натисніть **Save**.
6. Зачекайте приблизно 1–3 хвилини та оновіть сторінку.
7. GitHub покаже адресу сайту. Зазвичай вона має вигляд:

```text
https://YOUR_USERNAME.github.io/zatiya-feedback/
```

Це ваш `SITE_URL`.

## 9. Перевірте повний шлях відповіді

1. Відкрийте сайт із номером зустрічі, наприклад:

```text
https://YOUR_USERNAME.github.io/zatiya-feedback/?meeting=1
```

2. Поставте оцінку, виберіть відповідь на друге запитання та натисніть **Надіслати відгук**.
3. На сайті має з’явитися екран **«Дякуємо 💙»**.
4. Відкрийте Google Таблицю й перевірте, що в `Responses` з’явився новий рядок.
5. Перевірте значення `Meeting`, `Rating` і `NewIdeas`.
6. Видаліть тестовий рядок перед першою реальною зустріччю, якщо він не потрібен.

Якщо бачите повідомлення **«Форму ще не підключено»**, перевірте, чи вставили URL у `script.js` і чи завантажили оновлений файл на GitHub. Після оновлення GitHub Pages зачекайте хвилину й перезавантажте сторінку без кешу.

## 10. Створіть чотири посилання на зустрічі

Замініть `SITE_URL` своєю адресою GitHub Pages:

```text
Зустріч 1: SITE_URL/?meeting=1
Зустріч 2: SITE_URL/?meeting=2
Зустріч 3: SITE_URL/?meeting=3
Зустріч 4: SITE_URL/?meeting=4
```

Приклад:

```text
https://YOUR_USERNAME.github.io/zatiya-feedback/?meeting=1
https://YOUR_USERNAME.github.io/zatiya-feedback/?meeting=2
https://YOUR_USERNAME.github.io/zatiya-feedback/?meeting=3
https://YOUR_USERNAME.github.io/zatiya-feedback/?meeting=4
```

Для кожного посилання створіть окремий QR-код і підпишіть його номером зустрічі. Усі чотири QR-коди відкривають той самий сайт і записують відповіді до тієї самої таблиці; відрізняється лише значення у стовпці `Meeting`.

Якщо відкрити сайт без `?meeting=1`, `?meeting=2`, `?meeting=3` або `?meeting=4`, форма не прийме відповідь і покаже безпечне повідомлення про неправильне посилання.

## 11. Фільтруйте відповіді за зустріччю

1. У Google Таблиці виділіть перший рядок із заголовками.
2. Натисніть **Data → Create a filter**.
3. Біля заголовка `Meeting` натисніть значок фільтра.
4. Залиште позначеним потрібний номер: `1`, `2`, `3` або `4`.

## Якщо ви зміните Apps Script

Після змін у `Code.gs` натисніть **Deploy → Manage deployments → Edit** (значок олівця), у полі **Version** виберіть **New version** і натисніть **Deploy**. Зазвичай Web app URL залишиться тим самим.

## Які дані зберігаються

Скрипт записує лише:

- час відправлення;
- номер зустрічі;
- оцінку від 1 до 5;
- відповідь `Так`, `Частково` або `Ні`;
- дві необов’язкові текстові відповіді.

Ім’я, email, телефон, геолокація та ідентифікатори пристрою не запитуються і не записуються до таблиці.
